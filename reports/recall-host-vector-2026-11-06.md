# 召回分配、真实宿主与向量启动审查

日期：2026-11-06。输入均为合成需求，记忆库位于临时项目；不使用真实项目记忆。

## 召回分配

在联合召回中，先用有界词项索引确认项目候选是否超过原有预留槽位。仅在额度确有压力时，未匹配的全局软偏好退到未加载导航，把正文空间交给项目。全局强约束及关键词、任务意图、向量命中继续正常参与选择；没有匹配不等于没有适用性，主 AI 仍须按导航补读必要正文。

合成库含 1 条全局强约束、3 条无主题匹配的软偏好和 5 条相关项目规则。在相同 5 条／4000 字符请求下，正文分配从全局 3／项目 2 变为全局 1／项目 4。被推迟的软偏好没有删除、归档或被标记为已检查；其正文不增加召回次数。全局单独查询、空查询、无项目压力、项目召回关闭及项目正文字符额度为零时维持原有行为。

12 组交替顺序的本地关键词查询，原分配中位耗时 29.230 ms，新分配 38.267 ms。新策略多一次有界项目索引探测；本样本展示相关项目正文的覆盖改善，不代表检索提速或完整模型任务提速。未加载导航仍表示不完整，不将其缓存为全部已读取。

## 向量冷启动

按需运行 `python evals/vector_startup.py --runtime-root PATH`，其中 `PATH` 下已有 `vector-runtime/config.json`。工具只读取配置、使用固定合成文本并启动临时编码进程；不安装运行环境、不下载模型、不保存查询、不启动后台服务。它包装真实 `_infer` 路径计时，并与普通 `_encode` 的完整向量逐项比对。

本机一次阶段测量：

| 阶段 | 秒 |
| --- | ---: |
| 第三方模块导入 | 0.430 |
| Tokenizer 初始化 | 0.779 |
| ONNX 会话初始化 | 0.490 |
| 推理 | 0.066 |
| 进程启动、其他导入、I/O 与退出余量 | 0.374 |
| 包装路径总计 | 2.391 |
| 普通新进程参考路径 | 2.371 |

两条路径的全部向量值差异为 0。独立 tokenizer／模型初始化并行化在配对样本中为 2.55–2.58 s，顺序路径为 2.39–2.42 s；关闭 ONNX 预打包、跳过解释器清理也没有稳定收益，均未进入生产实现。保持原有模型、池化、5 秒查询预算和关键词降级路径。

真实运行环境下，向量／初始化／集成共 54 项测试通过、无跳过。实际索引 4.791 s／10 s，英文检索 3.396 s、中文检索 4.549 s／5 s；新增回归确认全局与项目共享一次编码，编码超时也共享失败预算。这些是新进程、已暖文件缓存下的本机测量；系统负载可能导致波动，不能当作所有 Windows/macOS 机器的延迟保证。
