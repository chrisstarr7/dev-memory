Dev Memory는 사용자가 명시한 요구, 수정 의견과 선택에서 재사용 가능한 개발 습관을 배우는 AI 코딩 도우미용 로컬 기억입니다. 프로젝트 규칙은 각 프로젝트에 보관하고, 기억·근거·수정 이력은 로컬 SQLite에 저장합니다.

[빠른 시작](#빠른-시작) · [작동 흐름](#학습과-조회-방식) · [기억 제어](#기억-제어) · [개인정보](#저장-위치와-개인정보)

## 기능

- 요구사항 분석, 구현, 문제 조사, 검증과 결과 전달에서 개인의 선호를 배웁니다.
- 현재 작업에 관련된 습관과 허용된 프로젝트 규칙만 소량 조회합니다.
- 일회성 지시는 현재 대화에만 적용하며, 새 프로젝트 기억 기록은 기본적으로 꺼져 있습니다.
- 호스트 지침과 로컬 Python CLI로 작동하며 상주 프로세스, 원격 측정, 외부 기억 서비스가 없습니다.

## 빠른 시작

프로젝트 루트에서 실행하고 `<agent>`를 아래 표의 AI 호스트 매개변수로 바꾸세요.

```sh
npx -y --prefer-online chrisstarr7/dev-memory <agent>
```

| AI 호스트 | 매개변수 |
| --- | --- |
| Codex | `codex` |
| Claude Code | `claude` |
| Cursor | `cursor` |
| Gemini CLI | `gemini` |
| GitHub Copilot | `copilot` |
| OpenCode | `opencode` |
| DeepSeek Harness(DSH) | `deepseek` |

필요 환경: Node.js 22+(npm/npx), Git, Python 3.10+(sqlite3). 설정 후 해당 프로젝트에서 새 AI 세션을 시작하면 됩니다. 매번 Skill을 다시 호출하거나 기억 저장을 요청할 필요가 없습니다.

Codex에서는 이 명령이 사용자 수준의 전역 습관과 현재 프로젝트 연결을 함께 설정합니다. 다른 호스트는 자동 사용을 위해 프로젝트별 설정이 필요합니다. 초기화되지 않은 프로젝트에서도 사용자 수준 지침을 쓸 수 있는 호스트는 현재 Codex뿐입니다. DeepSeek는 로컬 DSH를 뜻합니다.

**설치 후:** 새 세션에서 평소처럼 작업을 요청하고 수정 의견을 전달하세요. 개인 선호를 미리 넣지 않으며 실제 피드백으로 기억이 쌓입니다. 확인하려면 어떤 관련 습관을 조회했고 작업에 어떻게 반영했는지 AI에게 설명을 요청할 수 있습니다. 초기에는 관련 기억이 없어도 정상이며, 저장소에 접근하지 못하면 그 사실을 알려야 합니다.

## 기억 범위와 기본값

| 기억 | 예시 | 범위와 기본값 |
| --- | --- | --- |
| 전역 개발 습관 | 적합한 기존 구현 재사용, 근거부터 조사하기, 결과 보고 순서 | 프로젝트 정보를 제거한 뒤 여러 프로젝트에서 사용합니다. 허용된 호스트 설정에서 적합한 학습을 수행합니다. |
| 프로젝트 규칙 | 업무 제약, 설계 결정, 인터페이스 약속 | 해당 프로젝트에만 적용합니다. 새 프로젝트 기록에는 `full-project`가 필요합니다. |
| 일회성 지시 | “이번에는 테스트를 실행하지 마.” | 현재 대화에만 적용합니다. |

새 프로젝트의 기본값은 **`developer-first`**입니다. 기존 규칙은 조회할 수 있지만 새 프로젝트 기억은 추가하지 않습니다. 장기 프로젝트 기록을 추가하려면 `full-project`로 전환하세요. 업그레이드 시 기존 데이터와 설정을 보존합니다.

Codex 사용자 지침은 초기화되지 않은 프로젝트에서도 전역 습관을 사용할 수 있지만, 해당 프로젝트의 업무 기억을 초기화하거나 기록하지 않습니다. 다른 프로젝트에 독립 저장소와 프로젝트 규칙이 필요하면 그 프로젝트 루트에서 설치 명령을 실행하세요. 초기화된 프로젝트는 전역과 현재 프로젝트 기억을 한 번에 조회합니다.

## 학습과 조회 방식

```mermaid
flowchart TD
    A["개발자의 요청이나 피드백"] --> B["관련 기억 조회"]
    B --> C["현재 요청에 따라 작업"]
    C --> D{"장기 저장할 수 있는 새 정보인가?"}
    D -- "예" --> E["중복 확인·수정·저장"]
    D -- "아니요" --> F["결과 전달"]
    E --> F
```

일반 작업 흐름입니다. 중요한 정정은 관련 수정 전에 저장하고, 같은 작업에서는 유효한 조회 결과를 재사용합니다. 정리 대기 기억은 아래 조건에 따라 적절한 대화 경계에서 처리합니다.

1. **조회:** 작업 시작·재개 또는 주제가 실질적으로 바뀔 때 한 번 제한된 조회를 하고, 유효한 결과는 작업 중 재사용합니다.
2. **학습:** 명시적인 프로젝트 공통 선호는 확인된 습관이 될 수 있습니다. 재사용 가능한 사용자 요구, 선택과 정정은 처음부터 비활성 후보로 저장할 수 있고, 실제로 독립된 두 작업의 근거로 소프트 선호가 됩니다. 반복은 적용 조건이며 최초 기록의 조건은 아닙니다. AI 요약과 조회는 사용자 근거가 아닙니다.
3. **수정과 정리:** 새 기록 전에 기존 내용을 확인하고, 수정 요청이 있으면 기존 습관을 갱신합니다. 적절한 작업 경계에서 제한적으로 정리하며 현재 사용자 지시를 항상 우선합니다.

주 AI가 기존 작업 추론에서 피드백을 평가하고 최종 응답 전에 적합한 변경을 묶어 저장합니다. 새 정보가 없으면 쓰기나 NOOP 호출도 없습니다. 중요한 정정은 관련 수정 전에 저장하고 실제 저장 응답을 확인합니다. 기본 추가 모델 호출이나 상시 감시는 없습니다.

선택적 작업 의도(`--intent`)는 중영문 주제·본문 용어를 확장하며 분류로 검색을 제한하지 않습니다. 기본 본문 예산은 5개／4000자로 전역 습관 3개와 프로젝트 규칙 2개입니다.

변경 대기 5개, 본문 1200자 또는 미정리 변경 7일에 정리 알림을 반환합니다. 일반 응답에 정리 본문을 싣지 않습니다. 조용한 작업 경계에서 관련 묶음 하나(최대 8개／12000자)를 검토하고 동등한 규칙 통합, 중복 문장 축약, 태그 수정을 수행합니다. 이후 대화에서 이어지며 백그라운드 타이머는 없습니다.

## 기억 제어

| 목적 | AI에게 말하기 |
| --- | --- |
| 지속적인 습관 전달 | “모든 프로젝트에서 새 구현 전에 재사용할 만한 기존 코드를 확인해 줘.” |
| 프로젝트 기록 켜기 | “현재 프로젝트를 full-project로 전환해 줘.” |
| 기본 모드로 돌아가기 | “현재 프로젝트를 developer-first로 전환해 줘.” |
| 습관 수정 | “요구사항에 맞는 경우 기존 구현을 재사용하도록 수정해 줘.” |
| 전역 학습 일시 중지 | “전역 습관 쓰기는 멈추고 조회는 유지해 줘.” |
| 전역 기억 비활성화 | “전역 습관 조회와 쓰기를 모두 중지해 줘.” |
| 전역 기억 다시 시작 | “전역 습관 조회와 학습을 다시 시작해 줘.” |
| 이번 턴 제외 | “이번 턴은 기억에 저장하지 마.” |
| 확인 또는 삭제 | “관련 기억을 보여 줘.” / “삭제 범위를 미리 보고 확인 후 삭제해 줘.” |

## 저장 위치와 개인정보

| 저장소 | 기본 위치 |
| --- | --- |
| 사용자 전역 습관 | `~/.dev-memory/global/` |
| 현재 프로젝트 규칙 | `<project-root>/.dev-memory/` |

SQLite가 기준 데이터이며 Markdown은 읽기용입니다. 작업 절차는 전역 기록에서 프로젝트 이름, 업무 내용, 코드, 경로, 인증 정보와 원문 대화를 제외합니다. 프로그램은 알려진 민감 정보와 프로젝트 식별자를 차단하지만 의미상 비식별화는 AI가 담당합니다. 핵심 프로그램은 저장소를 업로드하거나 원격 측정을 수집하지 않습니다. 호스트 모델에 전달한 발췌문에는 해당 호스트의 데이터 정책이 적용됩니다.

명시적인 용량 확인은 `storage --scope global`(또는 `project`)로 합니다. `--reclaim`은 오래된 재생성 가능 캐시, 퇴역 검색 항목과 빈 페이지만 회수합니다. `--backup-keep N`은 보관안을 미리 보여 주며, `--reclaim`을 추가해야 검증된 동일 저장소의 이전 백업을 삭제합니다. 근거, 수정 이력, 개인정보·멱등성 기록은 보존하고 삭제에는 명시적 forget이 필요합니다. 고유 이력은 계속 늘 수 있어 무손실 고정 용량 상한은 없습니다. 일반 코딩 중에는 실행하지 않습니다.

## 기억이 저장되지 않을 때

설치된 CLI의 `doctor`를 한 번 실행해 `skill_version`, 사용자／프로젝트 활성화, 기록 제어와 후보／활성 기록 수를 확인하세요. GitHub만 업데이트해도 설치된 Skill이나 진행 중 세션이 바뀌지는 않습니다. 후보도 저장된 기억이지만 일반 조회에서 규칙으로 적용하지 않습니다. 필요한 경우만 `list --scope global --status candidate`로 확인하세요.

Codex 전역 습관만 활성화하려면 현재 설치된 CLI에서 `setup --user`를 실행하고 새 세션을 시작하세요. 프로젝트를 초기화하거나 일시 중지／비활성화를 해제하지 않습니다. 업무 규칙은 프로젝트 범위와 기록 모드를 따릅니다. 원인, 수정과 실제 검증은 [0.8.2 기록 검토](../../reports/capture-review-0.8.2.md)를 참고하세요.

## 업그레이드와 검증

업데이트는 초기화한 프로젝트에서 같은 설치 명령을 다시 실행하고 새 세션을 시작하세요. 데이터, 기록 설정, 관련 없는 지침은 유지하며 본문 변경 없이 내용 지문을 갱신합니다.

설치와 프로그램 검사는 실제 호스트 준수나 무시할 수 있는 지연을 증명하지 않습니다. [0.8.0 검토와 측정](../../reports/optimization-0.8.0.md)에 실측 결과와 검증 범위를 기록합니다. 호스트별 지침 지원과 실제 hooks 전달은 별도 검증이 필요합니다.
