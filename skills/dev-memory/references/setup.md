# Project initialization

Preferred online entrypoint: run `npx -y --prefer-online chrisstarr7/dev-memory codex` in the user's business project root, selecting the actual host. Add `--json` to inspect the receipt or `--project /absolute/project/path` when invoking from another directory. Codex installs both user-level global guidance and the current project binding; no second installation command is needed. Other hosts install project guidance. npx fetches the public GitHub package; its dependency-free Node launcher checks Python and calls the shared source installer with the original project, never the npm cache directory. Existing memories, controls and instructions are preserved. The installed Python runtime has no Node dependency. Without Node, use the Python online entry documented in the repository installation guide; it verifies the snapshot manifest and cleans temporary source.

This explicit command authorizes default project memory and merges host-native startup instructions. For Codex it also authorizes de-identified global habits across projects. Initialized projects make one combined global/project recall, not a second user-level recall; other projects use only the global store until initialized. No chat enable phrase or repeated Skill invocation is needed. Start a new host session to load new instructions; existing sessions may cache startup instructions. Offline source entrypoint is `python3 install.py codex --project /absolute/project/path` and configures both bindings.

From an installed Skill, use `python3 <skill>/scripts/dev_memory.py setup --agent codex --project-root /absolute/project/path`. The project argument defaults to the current working directory for this explicit command, including non-Git projects. Never run it in a downloaded package or unrelated project accidentally.

Host files: Codex uses existing nonempty root `AGENTS.override.md` when present, otherwise `AGENTS.md`; Claude Code uses `CLAUDE.local.md`; Cursor uses `.cursor/rules/dev-memory.mdc` with `alwaysApply: true`; Gemini uses `GEMINI.md`; Copilot uses `.github/copilot-instructions.md`; OpenCode and DeepSeek Harness use `AGENTS.md`. DSH uses the `deepseek-harness` binding; install selectors `deepseek` and `dsh` are aliases. Its default Skill root is `~/.dsh/skills`, with `DSH_HOME` respected and explicit `--target` taking precedence. Installation does not alter model configuration or grant host permissions. Existing content outside the managed block is preserved. No override is created that would hide existing team instructions. The files contain only the generic protocol; private runtime paths stay in the project's Git-excluded activation manifest. Existing tracked instructions can show a managed block change in Git; review it normally.

Inspect overall `status`, `project_setup`, its store results and `activation`, and Codex `user_activation`. Both bindings must be configured for successful unified Codex installation. A failure may leave one initialized store or installed program; it does not certify enabled memory. Project write failures do not route project content globally. Setup is idempotent and preserves namespace, data, paused and read-only settings. Do not use setup to undo a user's pause.

`doctor --project-root ...` reports `project_activation` separately from event hooks. Configuration never certifies actual host loading, per-turn execution, or model compliance. Initializing another project is a separate explicit action. Enabling memory in A does not authorize capture in B or make A's business global.

The low-level `init --global --project-root ...` command only creates stores; it does not install host instructions. It remains available for programmatic tests and specialized integrations. Read-only recall creates neither store nor instruction files.
