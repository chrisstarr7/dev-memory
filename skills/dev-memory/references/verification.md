# Verification and evaluation limits

## Test categories

- **Program tests** can verify routing, transactions, scope isolation, validation, exact receipt states, bounded SQL results, data deletion and filesystem behavior using synthetic temporary stores.
- **Semantic evaluation** asks whether an AI correctly inferred scope, retained conditions/negative constraints, avoided forbidden data, and resumed the right task. Program unit tests cannot prove these natural-language judgments. The source repository contains `evals/scenarios.json` for S01–S48; the installed runtime does not bundle evals.
- **Host end-to-end** distinguishes automatically loaded project instructions from enforced hook events. The former requires actual ordinary-prompt sessions on a named host/version; the latter additionally requires trusted, configured hooks and observed events. Synthetic protocol tests are not host E2E.
- **Latency comparison** must measure whole model tasks. SQLite timings alone are not workflow latency. Compare the same code snapshot, task, model and reasoning setting over repeated randomized trials for `off/on × empty/history`.

## A/B runner

The source checkout also provides `python3 evals/check_memory_quality.py --model EXACT_MODEL --reasoning high --output /absolute/path/outside-repo/result.json`. It compares identical tasks with and without memory, alternates pair order across repetitions, and records actual successful body delivery, independently executed artifact correctness, observable forbidden legacy output, available input/cache/output tokens and full task time. The off condition contains neither an installed user Skill nor stores: merely deleting AGENTS does not prevent host Skill discovery. Failures, missing artifacts and missing usage remain explicit. `--runtime-ref COMMIT` freezes an earlier runtime for replay; `--disclosure auto` exercises the optional compact/preview path; `--cases long` tests a long rule whose exception is beyond the preview. Two repetitions are a small regression baseline, not the randomized performance benchmark required for broad speed/accuracy claims below. Missing artifacts are never counted as successful rejection of a bad memory. Host-capacity failures remain distinct from completed product behavior; no automatic retry or model substitution is performed.

For a focused fresh-conversation check, run `python3 evals/check_cross_session.py --model MODEL --reasoning EFFORT --output /absolute/path/outside-repo/result.json` from the source checkout. This explicitly makes two real Codex calls using the existing login, isolated temporary home/stores and synthetic requirements. The first ordinary prompt states a durable requirement without requesting memory operations; the second fresh conversation receives only an implementation task. The check requires an actual saved body returned to the second conversation and independently validates its generated XLSX path, worksheet name and blankness. A cache hit, model success claim or installed guide alone cannot pass. Raw synthetic transcripts stay outside the public repository; temporary credentials and stores are removed. This sample does not certify every future conversation or other hosts.

For meaning and correction checks, run `python3 evals/check_memory_fidelity.py --model MODEL --reasoning EFFORT --output /absolute/path/outside-repo/result.json`. Three isolated Codex conversations capture a scoped rule with a caller override and a rejected alternative, correct only its default, then implement it without restating those values. The check executes the generated exporter and inspects both default and override artifacts, checks soft global status and revision reuse, and preserves stored bodies/evidence for source-by-source review. `behavior_checks_passed` explicitly leaves `semantic_review: required`: inspect all current fields and evidence for unsupported additions (including invented invalid-input fallbacks), missing qualifiers and old contradictory values. Assertions test specific outcomes, not a general natural-language accuracy score. It uses the existing login, temporary stores, no hooks/model downloads, and removes temporary credentials and projects on exit.

In the source repository, `python3 evals/bench_compare.py --help` documents the explicit model-runner. It creates isolated scratch copies and stores, invokes `codex exec --json` with a fixed model and reasoning setting, and writes a JSON report to a caller-chosen output. The harness records whole invocation wall time, first observable tool action as a proxy, tool event count, and available token fields. It sums input and output tokens once; cached input is already included in input tokens. The default recovery scenario checks key code strings and runs generated unit tests when present. `--scenario automatic-maintenance` supplies the same complete user policy to all conditions and also runs six independent behavior cases. Host failures, unknown correctness and completed-only timing must remain separate; a failed invocation is not a fast successful task. Structured host errors are retained when emitted. These measures do not establish semantic correctness; retain final messages and test output for review. It does not claim tool-action events equal every hidden model/tool operation.

Compare each condition separately (`memory off/on × empty/history`) with identical task text and starting code, at least three shuffled repetitions per condition, one named model and reasoning setting. Report medians and ranges for first action and full task, observed calls, available token counts, correctness, and missing constraints. Empty-store and seeded-history cases answer different questions. A seeded store in the off condition remains inaccessible by construction; this measures behavior without memory access, not a model's latent knowledge.

Do not benchmark with personal repository data or a production memory store. Inspect prompts and scratch cleanup policy first. Use at least three trials per cell, randomize cell order, record the model/reasoning/version, report medians and range, and include token unavailability. A benchmark of zero-delay NOOP tasks is not evidence about coding-task latency.

## Startup, resume and compaction acceptance

Run `python3 evals/check_host_delivery.py --model EXACT_MODEL --reasoning high --output /absolute/path/outside-repo/result.json` explicitly from the source repository. It uses the installed Codex app-server's real `thread/start`, a restarted process plus `thread/resume`, and `thread/compact/start`. Each phase gets a new random rule marker in a temporary project database that was never in the preceding model history. A phase passes only if successful `context --force` output contains the current project revision and the global body, and independently executing the generated module produces the exact new UTF-8 artifact. Empty cache receipts, assistant claims, failed turns and old artifacts are rejected. Temporary credentials, sessions and projects are removed; no hooks, hook trust bypass, model downloads or production services are involved. This is an opt-in developer acceptance tool, not a routine startup dependency. See the source repository's `reports/host-delivery-review.md` for actual host/model coverage; other hosts are not implied by a Codex pass.

## One-sentence correction acceptance

For explicit one-sentence correction acceptance, run `python3 evals/check_one_sentence.py --model EXACT_MODEL --reasoning high --output /absolute/path/outside-repo/result.json`. It makes three real, independent Codex conversations in disposable homes/projects: a synonym correction of an inactive project rule, ambiguous targets, and a temporary exception. No real memories or models are initialized. The original synonym query is required to miss, so successful correction must bridge different wording. Structural checks reject duplicate bodies, activation, lost exceptions/history/evidence and unintended changes. A primary-AI review must also compare the actual prompts, every changed field and final replies; the JSON deliberately reports that semantic review remains required. A successful sample is not a guarantee for other models or future tasks.

## Known limits

Codex events can run concurrently; hook trust is host-controlled. This package cannot ensure that implicit skill selection occurs every turn, cannot query host trust state through the CLI, and cannot enforce semantic correctness. Git status plus metadata is an invalidation aid rather than a content snapshot. Standard library credential patterns are incomplete. Deleted text may remain in filesystem snapshots or other databases. The package uses MIT. Source reports separate historical runs from the 0.4.0 prepublication maintenance sessions and incomplete A/B. Two ordinary Codex CLI sessions observed merge/compact and fresh-session duplicate prevention; they do not establish every-turn enforcement. The 12-attempt A/B completed 8 tasks, had 4 host exits, and measured significant overhead; final record-scope guidance was not rerun on the model. No automatic disk-size cap exists.

The 0.8.0 optimization has additional [program and exploratory real-host evidence](https://github.com/chrisstarr7/dev-memory/blob/main/reports/optimization-0.8.0.md). Exploratory sequential cells are diagnostic observations, not the randomized repeated benchmark specified above. Read exact source hashes, failures and semantic compliance separately from timing.
