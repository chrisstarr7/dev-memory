# Verification and evaluation limits

## Test categories

- **Program tests** can verify routing, transactions, scope isolation, validation, exact receipt states, bounded SQL results, data deletion and filesystem behavior using synthetic temporary stores.
- **Semantic evaluation** asks whether an AI correctly inferred scope, retained conditions/negative constraints, avoided forbidden data, and resumed the right task. Program unit tests cannot prove these natural-language judgments. The source repository contains `evals/scenarios.json` for S01–S48; the installed runtime does not bundle evals.
- **Host end-to-end** distinguishes automatically loaded project instructions from enforced hook events. The former requires actual ordinary-prompt sessions on a named host/version; the latter additionally requires trusted, configured hooks and observed events. Synthetic protocol tests are not host E2E.
- **Latency comparison** must measure whole model tasks. SQLite timings alone are not workflow latency. Compare the same code snapshot, task, model and reasoning setting over repeated randomized trials for `off/on × empty/history`.

## A/B runner

In the source repository, `python3 evals/bench_compare.py --help` documents the explicit model-runner. It creates isolated scratch copies and stores, invokes `codex exec --json` with a fixed model and reasoning setting, and writes a JSON report to a caller-chosen output. The harness records whole invocation wall time, first observable tool action as a proxy, tool event count, and available token fields. It sums input and output tokens once; cached input is already included in input tokens. The default recovery scenario checks key code strings and runs generated unit tests when present. `--scenario automatic-maintenance` supplies the same complete user policy to all conditions and also runs six independent behavior cases. Host failures, unknown correctness and completed-only timing must remain separate; a failed invocation is not a fast successful task. Structured host errors are retained when emitted. These measures do not establish semantic correctness; retain final messages and test output for review. It does not claim tool-action events equal every hidden model/tool operation.

Compare each condition separately (`memory off/on × empty/history`) with identical task text and starting code, at least three shuffled repetitions per condition, one named model and reasoning setting. Report medians and ranges for first action and full task, observed calls, available token counts, correctness, and missing constraints. Empty-store and seeded-history cases answer different questions. A seeded store in the off condition remains inaccessible by construction; this measures behavior without memory access, not a model's latent knowledge.

Do not benchmark with personal repository data or a production memory store. Inspect prompts and scratch cleanup policy first. Use at least three trials per cell, randomize cell order, record the model/reasoning/version, report medians and range, and include token unavailability. A benchmark of zero-delay NOOP tasks is not evidence about coding-task latency.

## Known limits

Codex events can run concurrently; hook trust is host-controlled. This package cannot ensure that implicit skill selection occurs every turn, cannot query host trust state through the CLI, and cannot enforce semantic correctness. Git status plus metadata is an invalidation aid rather than a content snapshot. Standard library credential patterns are incomplete. Deleted text may remain in filesystem snapshots or other databases. The package uses MIT. Source reports separate historical runs from the 0.4.0 prepublication maintenance sessions and incomplete A/B. Two ordinary Codex CLI sessions observed merge/compact and fresh-session duplicate prevention; they do not establish every-turn enforcement. The 12-attempt A/B completed 8 tasks, had 4 host exits, and measured significant overhead; final record-scope guidance was not rerun on the model. No automatic disk-size cap exists.
